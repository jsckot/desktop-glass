# 桌面玻璃分组 MVP 设计

2026-10-22，状态：按用户本轮体验反馈修正设计；旧版 0.1.0 不满足原生桌面交互要求。
目标环境仍为本机 Windows 11 26H2 / 26300.9711 x64。

## 用户确认的体验

- 在 Windows 原生桌面上增加独立的大文件夹分组组件，组内图标直接可见，参考用户提供的手机大文件夹图片。
- 组件之外保留 Windows 原生鼠标左右键、框选、拖动、刷新和图标操作，不铺设拦截输入的全屏覆盖层。
- 未分组的图标仍由 Windows 显示，原有位置不变；不再提供替代原生桌面的“未分类”侧栏。
- 从原生桌面拖入分组时，只收录引用，并临时隐藏该图标；真实文件、文件夹和快捷方式路径及属性不变。
- 从分组移出、删除分组、正常退出、崩溃恢复后，被收纳图标回到收纳前的位置。
- 重启应用保留分组和组内顺序；恢复过程按图标身份识别，不能靠易变的列表下标。
- 外接屏缺失时分组临时收纳，不覆盖保存的显示器及位置；屏幕接回后恢复布局。
- 卡片名称、大小、圆角与玻璃浓度可调；第一轮保持原图标、使用静态玻璃效果；暂不扩展任务栏和全系统图标美化。

## 对旧版的纠正

旧版用全屏透明窗口替代桌面图标视图，隐藏全部原图标，并接管空白处右键。这与本轮明确要求不符，不能作为新版的基础交互继续交付。
用户反馈旧版实际桌面不显示卡片；旧 UI 自检仅生成离屏 VisualBrush 预览并确认退出恢复，没有验证最终桌面合成。旧“UI 检查通过”不代表用户看到界面正常；修正验收必须覆盖真实显示和操作。

## 技术决策及待验证门槛

保留 C# / .NET / WPF 的配置模型、玻璃卡片及打包能力；重做 Windows 桌面接入边界。每个分组只占自己的组件区域，桌面其余区域不接收本程序的鼠标事件。新建分组入口放在托盘及组件菜单，不替换 Windows 桌面菜单。

在实施逐项隐藏前，先验证本机 Shell 能力：

1. 通过 Windows Shell 接口读取稳定图标身份、原坐标及自动排列状态。
2. 验证仅从视图移除一个图标而不移动真实文件、不改变文件属性，并可重新加入和定位。
3. 验证刷新、自动排列、Explorer 重建、显示器改变和异常退出时，不丢失图标、不扰动其他图标。
4. 原坐标及恢复日志成功落盘、恢复辅助进程就绪后，才允许隐藏。

微软的 `IShellFolderView.RemoveObject` 文档说明：移除的项目可能随时由数据源重新加入，接口也可能在后续版本改变或不可用。其所属 IShellFolderView 接口还被官方标为 Windows 7 起不再可用。本机只读探针 QI 返回 E_NOINTERFACE，当前客户端不能使用此直接调用路径；不能把头文件有声明或单次调用成功当作稳定隐藏能力，也不能据此宣称兼容所有 Windows 11。
若本机不存在可满足约束的接口，明确上报验证结果，不能偷偷改成移动文件、设置 Hidden 属性、将图标搬到屏幕外、关闭自动排列、注入 Explorer，或重新隐藏整个桌面。

## 验收场景

1. 启动前记录原生图标与坐标；启动后未分组图标位置、桌面空白处右键与框选保持原生。
2. 创建分组后实际屏幕出现玻璃组件；能够拖动标题和调整尺寸，普通应用窗口不受遮挡。
3. 将原生图标拖入组件：组件出现该图标，原桌面仅该项隐藏；双击打开原对象，文件路径和属性不变。
4. 移出、删除组、正常退出和杀死测试进程：被收纳项回到原坐标；与本程序无关的用户布局修改不主动覆盖。
5. F5/右键刷新不造成持续重复图标；Explorer 重建时安全恢复；自动排列等不满足约束的情况必须显式处理。
6. 外屏插拔、分辨率/DPI变化不覆盖偏好位置。真机未测试的场景明示，不用模型测试代替。
7. UI 验收包含实际桌面呈现及真实鼠标操作；离屏图只作样式证据。

## 数据与卸载

沿用用户级安装和有界清理。分组存引用、显示器身份、组件布局与风格；原生图标恢复数据独立保存。恢复失败时保留恢复日志和可操作的修复途径，不能当作成功清理。
卸载先停止实例并恢复被收纳图标，再删除软件拥有的文件和配置；不删除用户桌面内容。临时证据仍只写项目 `.codex/`。
