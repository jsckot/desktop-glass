# 桌面分组玻璃 MVP Implementation Plan

**Goal:** 在本机 Windows 11 26H2 上交付可安装体验的桌面玻璃分组。
**Spec:** [设计基线](mvp-design.md)。
**Architecture:** C# / .NET 10 / WPF；纯领域层负责分组布局，Windows 层负责 Shell、宿主与恢复，应用层负责交互，安装入口与诊断工具复用应用程序。
**执行方式:** superpowers:executing-plans，单代理实施、最终独立只读审查。临时证据全部在项目 `.codex/tmp/desktop-glass/`；不运行技能默认的 `.superpowers` 脚本，遵守用户路径约束。

## Global Constraints

- 本地分阶段提交，中文消息；不 push、不创建 PR、不合并。
- 不移动真实文件，不持久改变 Windows 桌面可见性，不注入 Explorer。
- 多屏临时回退不得覆盖保存位置；恢复通过后才默认启用接管。
- 包含 SDK、构建产物、截图和日志的 `.codex/` 不加入 Git。

## 阶段 1：基础模型与可验证布局

- [ ] 建立 Core 与无外部测试框架依赖的测试执行器；`dotnet run --project tests/DesktopGlass.Tests` 返回非零代表失败。
- [ ] 先写失败测试：唯一归属、移除不删文件、内部排序、缺屏临时回退、重接恢复、缩小工作区、无穷与非法尺寸、原子持久化损坏不覆盖。
- [ ] 实现 `Workspace`、`Group`、`Placement`、`LayoutResolver`、`WorkspaceStore`。
- [ ] 执行全部领域测试，提交 `feat(core): 实现桌面分组与多屏布局模型`。

## 阶段 2：Windows 桌面接入与恢复

- [ ] 通过 Shell 枚举桌面入口和图标；使用设备接口路径识别显示器，获取屏幕工作区和 DPI。
- [ ] 在正式接管前建立恢复日志、启动辅助监控并等待就绪。
- [ ] 建立桌面子窗口；临时隐藏图标视图；退出、辅助进程及下次启动幂等恢复。
- [ ] `--diagnose` 只读输出系统、显示、Shell 项目计数与宿主能力；`--smoke` 检查宿主与退出恢复，`--crash-test` 检查强制终止恢复，证据仅写 .codex。
- [ ] 记录当前 build 的验证结果，再提交 `feat(windows): 接入桌面宿主与异常恢复`。

## 阶段 3：玻璃分组交互

- [ ] 实现卡片、原生图标、未分类区域、拖拽归属与排序、创建重命名删除、移动缩放、透明度圆角、锁定、托盘退出。
- [ ] 壁纸模糊采样与轻薄高光统一外观；无持续背景动画；不可采样壁纸时降级半透明底色。
- [ ] 屏幕拓扑变化只更新呈现；缺屏项收纳且不回写。新增文件刷新可见。
- [ ] 构建、交互自检及截图检查，提交 `feat(ui): 实现玻璃分组与桌面交互`。

## 阶段 4：发布、安装卸载与交付

- [ ] 用户级安装和卸载；安装目录所有权标记与清理边界；卸载前通知主进程正常恢复。
- [ ] 自包含单文件发布，制作体验包，记录真实体积和空闲资源采样。
- [ ] 构建与领域/Windows 检查，独立审查并修复；审查证据对应最终提交。
- [ ] 更新 `docs/acceptance.md`，明确真实双屏及睡眠等尚未实测场景。
- [ ] 提交 `build(release): 提供本地安装体验包与验收记录`，交付安装路径和限制。

## Review Focus

1. 接管失败或主进程退出，原图标是否恢复；窗口句柄复用是否影响其他窗口。
2. 外屏断连时是否覆盖原位置；同屏型号或接口改变是否错误匹配。
3. 新文件、虚拟 Shell 入口和失效快捷方式是否仍可访问。
4. 数据损坏、程序多开、运行中卸载是否丢失用户数据。
5. 清理是否严格限制软件拥有目录；图标及 GDI/COM 资源是否释放。

## 2026-10-22 执行状态

- 阶段 1、2、3：实现与当前单屏自动检查完成，分别进行了本地提交。
- 阶段 4：自包含目录发布、隔离安装、正式卸载清理器及中断修复通过；独立审查通过。目录式发布替代原拟单文件方案，避免提取缓存残留。
- 自动验证：领域 13 项通过；Windows 六种模式通过，安全模式内含 9 项检查。详细证据和边界见 [验收记录](acceptance.md)。
- 交付级别：可安装的本地体验版。真实外屏、真实账户安装/卸载、Win+D 等手动场景待用户体验；轻量化目标尚未达到，不宣称所有性能/兼容验收完成。
- 无用户授权不推送、建 PR 或合并；后续范围在体验后确定。
