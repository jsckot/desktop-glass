# Desktop Glass 0.4 Implementation Plan

日期：2026-10-23。基线 `a26b8d3`，分支 `feat/desktop-groups-mvp`。用户授权继续优化实时玻璃、视觉以及鼠标悬停展开，并明确选择收起后显示名称和少量图标的紧凑方块。

## 设计与边界

- 默认收起为约 144 DIP 方块，标题及最多四个入口缩略图；进入展开为已保存的完整分组尺寸。离开延迟约 450ms 收起，进入延迟约 120ms 防止路过误触。
- 拖拽、尺寸/位置手势、菜单、键盘操作期间保持展开；收起释放真实 HWND 占用范围，使周围桌面继续接受 Windows 输入。复用原 HWND，悬停不写配置，展开尺寸与布局独立于收起显示状态。
- 靠边时展开位置夹紧至当前工作区，收回原紧凑锚点；展开/收起不能修改原屏幕偏好或把紧凑尺寸保存为完整尺寸。
- 去掉圆角滑块，统一为 12 DIP 轻圆角。旧配置中的 Radius 保留可读，不因外观升级破坏存储；当前版本仅呈现统一圆角。
- 清除静态壁纸采样造成的错位玻璃。优先验证系统合成实时背景是否能用于当前桌面宿主，包含非激活状态；不通过连续屏幕截图模拟，不改其他程序或 Explorer 的样式，不新增常驻高频轮询。
- 若现有原生桌面子窗口无法获得实时背景，必须提供实验证据并明确技术限制；不把接口成功当视觉验收、不以静态壁纸伪装实时效果。未经实证不改变桌面层级架构。
- 视觉以低饱和冰蓝/中性色材质、细边缘、紧凑清晰的图标与文本为主；保留原文件图标辨识，避免夸张的高光与白色覆盖。

## 执行

实验证据更新：自有 child HWND 的 HostBackdrop 无效；顶层 HWND 可透出实时彩块，用户确认失去焦点仍保持模糊，WPF 文字与按钮可见且点击成功。因此采用顶层 HostBackdrop，并增加仅操作自有 HWND 的桌面层管理器。默认置于普通应用下、Explorer 桌面上；临时前景仍为显式开关。共享 WinEvent 通知合并后重排，不轮询截图、不改 Explorer。此变更需额外检查普通应用遮挡、Win+D、关闭后不复活及资源释放。

层级裁决：直接使用桌面前驱遇到受保护的 IME/ASUS 辅助窗口会拒绝访问；曾验证的桌面 owner 方案在最小化恢复时会抬高 owner，已废弃。最终无 owner 写入，仅将自有窗口下放并校验实际顺序，非底部根才显式定位；真实 Progman 探针确认三个阶段的 443 个外部窗口相对顺序未变。`anchor-probe.txt` 初次未记录 BOTTOM 后的实际顺序，不作为当时“无 owner 会落到桌面下”的推断证据；以 `real-layer-v5.json` 与原始 Harness 为准。

高风险：悬停几何状态改变控制器与原生宿主边界；材质涉及系统合成与桌面层级。需要独立只读审查。原已安装进程保持运行，所有测试使用项目内隔离配置、自有空窗口，不获取全局项目租约或触碰用户图标。
